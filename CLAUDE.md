This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Install dependencies (run from root)
npm install
cd server && npm install

# Development (frontend + backend concurrently)
npm run dev

# Frontend only
npm run dev:client

# Backend only
npm run dev:server

# Production build
npm run build
```

No test framework exists in this project.

## Environment Variables

Frontend (`.env`):
- `VITE_API_URL` — backend URL (default: `http://localhost:3001`)

Backend (`server/.env`):
- `MONGODB_URI` — MongoDB connection string (default: `mongodb://localhost:27017`)
- `DB_NAME` — database name (default: `finanza_tracker`)
- `PORT` — server port (default: `3001`)
- `JWT_SECRET` — secret for signing JWTs (required in production)

## Architecture

**Stack**: React 18 + Vite (frontend) · Express + Node.js (backend) · MongoDB Atlas (database)

**Deployment**: Vercel (frontend) · Render (backend) · MongoDB Atlas

```
React SPA (Vercel) ──REST──▶ Express API (Render) ──▶ MongoDB Atlas
       │                                                     │
       └──── localStorage fallback (if API unreachable) ─────┘
```

### Frontend

All UI lives in a single monolithic `src/App.jsx` (~3200 lines). Six screens rendered conditionally by a `view` state variable:

| Screen | Component | Purpose |
|--------|-----------|---------|
| Login | `LoginScreen` | PIN entry, registration, fast-login with cache |
| Home | `HomeView` | Transaction list, month filter, debt settlement |
| Add/Edit | `AggiungiView` | Transaction form, multi-person splits |
| Stats | `StatsView` | Charts, category breakdown, trends |
| Portfolio | `PortfolioView` | Stock positions + live Yahoo Finance quotes |
| Export | `ExportView` | XLSX/CSV import-export |
| Settings | `ImpostazioniView` | Custom categories, account management |

`src/api.js` wraps all REST calls with localStorage caching and offline fallback logic.

### Backend

Single file `server/index.js` — Express app with MongoDB driver (not Mongoose). Collections:
- `households` — household config, persons, PIN, custom categories
- `transactions` — scoped to `householdId`
- `positions` — stock portfolio entries
- `quotes_cache` — daily Yahoo Finance quote cache

Auth uses a `x-household-id` header on every request after login. PIN is stored as bcrypt hash.

### Key Patterns

**Offline-first**: Every write goes to localStorage immediately; API sync happens in background. On load, app renders from cache, then reconciles with server.

**Fast login**: On first login, PIN hash (SHA-256) and household data are cached in localStorage. Subsequent logins match hash locally, complete in ~0ms with a 6s background sync timeout vs. 20s cold-start timeout without cache.

**Multi-person splits**: Transactions support `splits[]` with per-person `quota` (percentage). A greedy settlement algorithm in `calcolaDebitiMatrix()` computes minimal debt transactions across all household members.

**Recurring transactions**: Stored with `ricorrenza.frequenza` + `ricorrenza.prossimaData`. On app load, overdue recurrences are auto-generated by checking all transactions with a `ricorrenza` field.

**Quote caching**: Stock quotes from `yahoo-finance2` are cached in MongoDB for 24h. Force-refresh is available via query param.
